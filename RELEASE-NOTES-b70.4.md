**0.32.0-b70.4**: both attention variants of the 0.32 line are working, on one code base.

**Dense** (`v0.32/patches/vllm/`, now 50 patches; fork tag `v0.32.0-b70.4-dense`). Patches 0001–0049 are unchanged from 0.32.0-b70.1. New **0050** backports vllm-project/vllm#54163 (merged upstream 2026-10-23): DFlash and DSpark no longer drop the trailing prefix-cache block, so `disable_eagle_block_drop` is no longer set in `v0.32/engines/serve.args`. Both engine files run **12 sequences** (capture sizes at every multiple of 8 up to 96). The dense numbers in the README were taken at 8 slots; the dense engine at 12 slots was not re-measured.

**Sparse (QSA)** (`v0.32/patches/vllm-qsa/`, now 36 patches; fork tag `v0.32.0-b70.4`; working, experimental). The sparse engine packed its KV cache into 7 large groups, so every small per-request state group paid whole 10.9 MB blocks. Patches 0033 and 0036 split that into 66 groups of 905,216 B blocks, **on by default** (`B70_KV_SPLIT_GROUPS=0` restores the old packing). Outputs are unchanged (KL against unsplit sparse at its own noise floor); GPU KV is 344,706 tokens and the agent replay's GPU prefix hit rate goes from about 0.37 to about 0.46. 0034 adds `B70_QSA_OPTIMER`, a per-op timer (off by default); 0035 a cache-path lifecycle driver with tests.

**Sparse against dense, same trunk code, back-to-back boots.** Agent-session replay: about 205 s against about 232 s (median decode 61–69 against 45–52 tok/s). Short context 0.90–0.97× dense (one-stream decode 0.92×, 8 streams 0.93×, prefill up to 32K 0.89×). Long prefill: 131K 1.06×, 260K 1.31×. Long-context tasks (384 items): equal up to 8K, 128K 80/78 % against 72/72 %; real-document next-token loss at 32–128K 1.399 against 1.417. GPU KV 344,706 against 397,309 tokens. Not measured: generation or reasoning quality against dense (the tasks are retrieval-type), a multi-day run, the stock oneCCL plugin with sparse. Details and caveats: `docs/measurements/v0.32-qsa.md` §0.

**Kernels unchanged:** vllm-xpu-kernels `release/0.1.15.4` plus the 64-bit GDN conv-state offset patch. 0.1.16.2 from PyPI was tried and not taken: it does not contain upstream #658 (`large_state_offset` fails 3 of 3 on a card); re-test when a wheel after #658 appears.

**Tooling.** `tools/check-trunk-tree.sh` gains `--hotcold-tip`; `v0.32/scripts/check-series.sh` and `--qsa` default to the b70.4 refs.
