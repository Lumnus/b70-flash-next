What we serve in this release (engines/s16-kv128-mtp3.env with `MODEL=awq`): wtdcode/Qwen3.8-Flash-Next-AWQ-W4A16 @
`0939125`; the alternative, Intel/Qwen3.8-Flash-Next-W4A16-AutoRound @ `4c67bf68`, is the same engine with
`MODEL=intel-autoround`. The numbers below come from the working branches that the release branch consolidates (known

Both: MTP with 3 draft tokens, 16 slots, 262K context, `--gpu-memory-utilization 0.88`, a 128 GiB CPU KV tier,
the INT8 PLE table served from NVMe, 0014jb, vllm-xpu-kernels 0.1.14.1+b70.3, on 4× Arc Pro B70 (TP4 + EP),

paired on identical items. Where a row says "b70.2 kernels", the measurement was taken on 0.1.14.1+b70.2: b70.3 adds

## 3. Host memory under the CPU KV tier (2026-10-03)

With kernels 0.1.14.1+b70.3, CPU→GPU KV loads copy straight from the pinned offload pool (B70-K1), and host memory stays
flat under KV reload load. Measured over two back-to-back replays of 6 real agent sessions at a 128 GiB CPU tier, against
the kernels' staged copy (`VLLM_XPU_H2D_BATCH_STAGING=1`, the upstream behaviour) and vLLM patch 0031:

| | staged copy | 0031 (`B70_OFFLOAD_H2D_DIRECT=1`) | kernels b70.3 (`B70_OFFLOAD_H2D_DIRECT=0`, what we serve) |
|---|---|---|---|
| xe host memory per rank | +2.56 GiB | +0.06 GiB | **+0.058 GiB, once, then flat** |
| CPU→GPU load bandwidth | 8–12 GB/s | 19.8 GB/s | 19.6–19.9 GB/s |
| 8 GiB host-RAM guard stops | yes | none | none |
| prefix reuse | 94.4 % | 94.4 % | 94.4 % |
| errors | — | 0 | 0 |

The staged copy takes a pinned buffer the size of each load from torch's host cache, which keeps blocks up to 1 GiB.
0031 is the same direct copy in vLLM, for kernels without B70-K1.

Prefix reuse is ~96 % in real use and 94.4 % in the replay. How it splits between the GPU pool (~311K tokens) and the
CPU tier depends on the workload: with 6 sessions in flight the GPU tier serves 46–55 % of prompt tokens and the CPU
tier the rest; with 3 sessions the GPU tier serves 91 %.

Real agent use, Intel build, 7.3 h, 1,955 requests (mean prompt 93K tokens): 182.1M prompt tokens, 96.6 % from cache
(GPU pool 31 %, host RAM 65 %), 3.4 % computed; 6,899 prompt tok/s on average (peak 32,553 over 1 min) against 230
computed tok/s. The AWQ build's window (2.7 h, mean prompt 59K tokens): 95.7 % from cache, GPU 54 %, RAM 42 %.

## 4. Running it (2026-10-03)

- Boot to the first generated token: ~6–7 min. Model 20.29 GiB per card; 311,299 KV tokens on the GPU; card 0 has
  ~0.7 GiB of VRAM free.
- Correctness gates on this definition: 0/90 bad simultaneous bursts, concurrency sweep 1–10 clean, 36 structured-output
  requests + 18 plain ones clean with MTP.
- Endurance: see §5. The Intel engine on the b70.2 kernels ran 21.5 h before two guard stops, both caused by
  full-vocab prompt logprobs, which 0029b fixes; Intel has no multi-day run on b70.3.
- Steady-state host memory on our 256 GiB host: ~39 GiB MemAvailable with AWQ, ~23 GiB with Intel.
